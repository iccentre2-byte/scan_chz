# Контракт, источники и границы интеграции

Проверка публичных источников: 11.10.2026. Полный закрытый/авторизованный ЛК пользователя не открывался. Ни один реальный документ, отчёт о нанесении или заказ кодов не подавался.

## Используемый контракт

Базовые серверы жёстко ограничены: промышленный `https://markirovka.crpt.ru`, тестовый `https://markirovka.sandbox.crptech.ru`. Клиент не переходит по HTTP-перенаправлениям с токеном.

- `GET /api/v3/true-api/auth/key` — строка для авторизации.
- `POST /api/v3/true-api/auth/simpleSignIn` — подписанная строка, UUID запроса, ИНН организации, единый токен. Поддержаны ответы с `token` и `uuidToken`. Используется присоединённая подпись случайных данных, не устаревшее подписание только ИНН.
- `POST /api/v3/true-api/cises/info?pg=grocery` — сведения о кодах, порциями до 100.
- `POST /api/v3/true-api/lk/documents/create?pg=grocery` — `document_format=MANUAL`, `type=SETS_AGGREGATION`, Base64 документа, откреплённая УКЭП.
- `GET /api/v4/true-api/doc/{documentId}/info?pg=grocery` — результат обработки.

Тело документа формирования, без реальных кодов:

```json
{
  "participantId": "<ИНН>",
  "aggregationUnits": [
    {"unitSerialNumber": "<КИН>", "sntins": ["<КИ пачки 1>", "<КИ пачки 2>"]}
  ]
}
```

Это формирование набора, не КИТУ/SSCC, не заказ кодов и не создание неподписанного черновика. Значения из упаковки нормализуются до КИ для True API; криптографический хвост полного Data Matrix не включается в КИ документа.

Успешный HTTP-ответ сам по себе не завершает операцию. Обычно требуются статус документа CHECKED_OK, подтверждённые владелец/статус SET и точное совпадение списка вложений. После неопределённого POST возможна проверка фактического состава без восстановления ID документа; это явно отражается в сообщении.

Нормализатор пилота рассчитан на бакалейный формат: AI01 + GTIN14 + AI21 + серийный номер 13 символов. Это не универсальный парсер всех товарных групп. Расширять его без реального образца/спецификации другой группы нельзя.

## Первичные источники

1. Честный ЗНАК — «Формирование наборов (Бакалейная продукция)», обновление 05.10.2026: https://markirovka.ru/knowledge/tovarnye-gruppy/bakaleinaya-produkciya/formirovanie-naborov-bakaleynoy-produktsii
2. Честный ЗНАК — «Формирование набора из единиц, принятых по ОСУ»: https://markirovka.ru/knowledge/tovarnye-gruppy/bakaleinaya-produkciya/formirovanie-nabora-iz-edinits-prinyatykh-po-osu-korma-konservy-rastitelnye-masla-ikra
3. Описание True API: https://docs.crpt.ru/gismt/True_API/ — единая аутентификация, создание документов, формирование набора и справочники. Поисковая копия части документа устаревала относительно официального журнала изменений; перед эксплуатацией сверить контракт с разделом «Помощь» ЛК.
4. Официальный журнал изменений: https://docs.crpt.ru/gismt/Exchange_en/ — изменение получения UUID-токена отмечено как внедрённое 10.06.2026.
5. КриптоПро — CadesSignedData: https://docs.cryptopro.ru/cades/reference/cadescom/cadescom_class/cadessigneddata
6. КриптоПро — кодирование подписываемых данных: https://docs.cryptopro.ru/cades/plugin/content-encoding
7. Android — совместимость AGP 8.2/JDK 17/SDK 34: https://developer.android.com/build/releases/agp-8-2-0-release-notes
8. PyInstaller — параметры сборки: https://pyinstaller.org/en/stable/man/pyinstaller.html

Практическая проверка права включения конкретных ОСУ-кодов остаётся за сервером ЧЗ. Локальная проверка не подменяет приёмку по ЭДО и не устанавливает право собственности. Недоступные/неожиданные ответы API блокируют подтверждение успеха, а не считаются разрешением на операцию.

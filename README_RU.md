# ЧЗ: Наборы 1.3.2 — удобный редактор профилей

В 1.3.2 профиль создаётся отдельной кнопкой. QR/DataMatrix набора и пачки заполняет только GTIN. Состав редактируется строками: GTIN, отдельное количество, кнопки «−» и «+». Новый профиль и копия выбранного сохраняются отдельно; совпадающее название не заменяет существующий профиль.

Инструкция: [docs/INSTALL_1_3_2_RU.txt](docs/INSTALL_1_3_2_RU.txt). Сохранены отдельная рабочая страница, поток, экспорт/импорт профилей и проверяемый перенос очереди. Единая копия профилей и очереди содержит проверяемый результат с идентификатором запроса. Секреты соединения и КЭП исключены. Подпись берётся только из GitHub Secrets.

`com.tsd.czsetcollector.safe` устанавливается рядом с пилотом при разных сертификатах. Обновление существующей программы допускается только с совпадающей подписью и подтверждённой копией. APK в корне репозитория относится к прежней версии; используйте релиз. Проверки CI подтверждают сборку и логику, а работу физического сканера и формирование новых документов следует проверять отдельно на устройстве.

## Предыдущая документация 1.3.0

Доработка проекта `scan_chz-main.zip` (1.2.4), 11 октября 2026 года.

**Статус:** исходники изменены, помощник реализован, локальные тесты пройдены. Это опытная версия для проверки одного набора, не подтверждённая промышленная сборка. В архиве НЕТ нового готового APK или EXE. Старый APK 1.2.4 намеренно не вложен, чтобы его не приняли за обновление.

## Что теперь делает комплект

ТСД сохраняет код набора и коды пачек → передаёт состав в локальную очередь ПК → пользователь на ПК проверяет состав и выбирает КЭП → помощник подписывает документ SETS_AGGREGATION и отправляет в True API → помощник проверяет обработку документа и фактические вложения набора → ТСД получает статус.

Сканирование и передача на ПК НЕ создают документ в ЧЗ. Для отправки обязательно отдельное подтверждение на ПК. КЭП и PIN на Android не передаются.

## Сначала — код маркировки самого набора

В этой версии заказ кодов в СУЗ, печать этикеток, отчёт о нанесении и редактирование Национального каталога остаются вне программы. Для физического набора используется ранее заказанный Data Matrix с типом «Набор». Это НЕ QR подключения ТСД к помощнику.

Официальная последовательность для бакалеи: карточка набора с составом → заказ кода набора → нанесение и отчёт о нанесении → формирование набора. Для выбранного сценария купленные вложения должны быть «В обороте», а пустой код набора — «Нанесён», тип эмиссии LOCAL. См. `docs/API_AND_SOURCES_RU.md`.

Пять пробных кодов пользователя не заменять и не списывать автоматически. Сначала проверить один существующий код. Если созданы только карточки в каталоге, но сами индивидуальные коды не заказаны, сканировать пока нечего.

## Один раз настроить

1. На ПК с КЭП запустить `companion_pc/Start_PC.cmd`. Нужен Python 3.11+; при первом запуске скрипт устанавливает две Python-зависимости. Готовый EXE отдельно собирается workflow и не входит в этот архив. Подробности в `companion_pc/README_PC_RU.md`.
2. ПК и ТСД подключить к одному роутеру. На ПК открывается локальная страница помощника. Нажать «Показать подключение / QR».
3. В новой Android-сборке нажать «Подключить ПК / QR» → «Сканировать QR». Сверить адрес и отпечаток сертификата с ПК. QR содержит секрет подключения, его не публиковать. Камера смартфона в этой версии не добавлена: используется штатный сканер ТСД или ручной ввод адреса, ключа и отпечатка.
4. Создать профиль: понятное название, свой ИНН, контур, 14-значный GTIN НАБОРА и состав из его карточки. Один GTIN вложения на строку: `GTIN=количество`. Для ассорти перечислить все разные GTIN с их количествами. Сумма 6 сама по себе не заменяет правильный состав.

## Ежедневная работа

Сканировать код набора первым. Затем сканировать пачки. Программа не принимает код самого набора как пачку, повтор той же пачки, неподходящий GTIN или превышение количества по вкусу/виду. При полной комплектации набор сохраняется в очередь ТСД, после чего можно собирать следующий.

Нажать «Передать готовые наборы на ПК». В очередь попадают только полностью собранные наборы. Если ПК недоступен, данные остаются на ТСД. Повторная передача того же задания не создаёт дубль на ПК.

На ПК нажать «Найти сертификаты», выбрать КЭП нужной организации, отметить сначала ОДИН набор, раскрыть «Проверить состав и документ», нажать «Подписать и отправить выбранные в ЧЗ» и подтвердить действие. В производственном контуре это реальный документ учёта, не черновик. PIN вводить только в штатном окне КриптоПро.

Для группы выбранных наборов одного ИНН и контура помощник последовательно отправляет по одному документу на каждый набор. Лимит выбора — 50. При ошибке последовательность останавливается, оставшиеся наборы не отправляются. Это намеренно облегчает контроль первого запуска.

После отправки:

- «На ПК: ожидает подписи» — в ЧЗ ещё ничего не отправлено.
- «Передан в ЧЗ» / «Обрабатывается» — результат ещё не подтверждён.
- «Сформирован: состав проверен» — подтверждены данные ЧЗ, а не только HTTP-ответ.
- «Отклонён ЧЗ», «Требуется проверка» или «Результат неизвестен» — не отправлять повторно вслепую.

Помощник проверяет активные отправки примерно каждые 20 секунд, пока действует полученная сессия. Android запрашивает статусы у помощника примерно каждые 10 секунд, пока открыт на экране. Таймеры не подписывают документы, не выполняют повторный вход по КЭП и не повторяют отправку.

## Работа с ОСУ

Программа не отбрасывает вложение только из-за того, что поле владельца отдельного кода содержит ИНН поставщика. Но это не отменяет контроля ЧЗ: наличие законного прихода по ОСУ и допустимость конкретных кодов проверяются системой маркировки. Приёмку ЭДО программа не выполняет и виртуальный склад не корректирует.

Этот пилот ограничен `grocery`: сухарики и майонезы. Поддерживается формирование из уже введённых в оборот единиц, не из «Нанесённых» вложений. Принадлежность к чужому транспортному агрегату не снимается автоматически: программа останавливает отправку и сообщает о необходимости разобраться с агрегацией.

## Сохранность и исправления

Android сохраняет текущий неполный набор и очередь после сканирования. ПК хранит очередь в SQLite с журналом переходов и резервированием кодов. При сбое записи сканирование останавливается вместо перезаписи пустой очередью.

Незавершённый набор можно сбросить на ТСД. Полностью собранный, но ещё не отправленный в ЧЗ, можно передать на ПК и отменить там. Затем обновить статусы на ТСД и собрать заново. Отмена на ПК — только локальная, это не расформирование в ЧЗ.

Если результат POST неизвестен, повтор автоматически запрещён. Сначала проверить ЧЗ и соответствующий документ. В этой версии нет кнопки принудительного повторного POST, автоматического исправления отклонённого документа или расформирования набора.

Кнопка резервной копии на ТСД экспортирует составы без ключа подключения. На ПК создаётся согласованная копия SQLite. Файлы содержат ИНН и маркировочные коды: передавать только себе/уполномоченному специалисту. Автоматический импорт копии через Android-интерфейс пока не реализован.

## Получение APK и EXE

Workflow `.github/workflows/build.yml` собирает Android и Windows-помощник, но здесь не запускался. Сначала выполняются тесты, затем создаются артефакты (без публикации релиза):

- `CHZ-Android-1.3.0-rc1-pilot` — опытный APK;
- `CHZ-Windows-helper-1.3.0-rc1` — EXE помощника с файлами запуска.

Пилотный APK имеет отдельный applicationId `com.tsd.czsetcollector.pilot`. Он не заменяет установленную 1.2.4 и не получает её настройки автоматически. Профили в пилоте нужно заполнить заново. Это защита от потери старых данных и несовместимости подписей APK.

Для обновления поверх старой программы нужен исходный ключ подписи APK, а не КЭП ЧЗ. Он в этот архив не включён. Не удалять старое приложение ради установки экспериментальной версии. У повторно собранных debug APK в разных CI-запусках подпись может отличаться: перед обновлением пилота сделать копии и обеспечить постоянный ключ подписи сборок.

## Проверки и ограничения

См. `docs/TEST_REPORT_RU.md`: 42 Python-теста, 24 проверки реального Kotlin-модуля Domain.kt, синтаксические проверки. Полная Android-сборка, работа сканера на ТСД, CAdESCOM на Windows и реальная приёмка документа ЧЗ ещё не проверены. Здесь нет Android SDK/Windows/КЭП, а загрузка средств сборки недоступна.

Не использовать массово до проверки одного из пяти пробных наборов. Заказ/печать кодов, отчёт о нанесении, передача на Ozon, выбытие при продаже, возвраты и расформирование не входят в этот комплект.
